# 🎤 Judge Q&A Prep — 20 likely questions

**1. Where does your data come from?**
Fully synthetic, generated by `generate_data.py` with a fixed seed — but matching
the real schemas of CCTNS FIRs, telecom CDRs, and FIU transaction reports. In
deployment the loaders are swapped for secure APIs; the pipeline is unchanged.

**2. Why not real data?**
Real crime data is legally restricted (and rightly so). SIH expects synthetic
data. Our schemas mirror the real ones so integration is a connector change.

**3. How is blockchain actually used — is it just a buzzword?**
No — it solves a concrete problem: officer accountability. Every query is a
block in a SHA-256 hash chain; editing any past block breaks all later hashes.
We demo this live (Tamper Test). Production: permissioned Hyperledger Fabric
across NCRB nodes, so no single admin can rewrite history.

**4. Can this falsely accuse innocent people?**
The system never accuses — it surfaces *leads with evidence attached*. Every
edge cites its source (FIR number, call count, transaction amount). A human
investigator validates everything. That's also why the audit trail exists.

**5. Privacy / DPDP Act 2023 compliance?**
Access is purpose-limited and logged immutably; role-based access control in
production; data stays inside government infrastructure (on-prem LLM, NIC
cloud). Aadhaar resolution happens only on the government side under existing
legal authorization.

**6. Scalability — this is 30 people; real data is millions.**
NetworkX is our prototype engine; the schema ports directly to Neo4j, which
handles billions of edges. PageRank/Louvain run on Neo4j GDS at that scale.
Ingestion parallelizes per-district.

**7. What about Hindi/regional-language FIRs?**
Prototype NER is English regex for demo reliability. Production: fine-tuned
IndicBERT/MuRIL NER — FIR narratives in 12+ languages. Same pipeline slot.

**8. How is the kingpin found if he's in no FIR?**
Financial centrality + operational invisibility: high net money inflow with zero
FIR mentions. Also shared infrastructure (burner, shell company) links him via
link prediction. That's the exact pattern real network heads show.

**9. What's your anomaly detection?**
Burst detection on per-pair call volumes (a day with ≥5 calls vs baseline
1–2). Production: time-series models (Prophet/ESD) and geo-fenced tower spikes.

**10. LLM hallucination risk?**
The LLM only *phrases* facts computed by deterministic graph algorithms — it
never invents connections. Prototype uses templates to show it works with zero
hallucination risk at all.

**11. Difference from existing tools (i2 Analyst's Notebook, Palantir)?**
Those are foreign, licensed, and manual-first. Ours is open-source (zero
licence cost), automated entity extraction from Indian FIR formats, built-in
blockchain audit for DPDP compliance, and LLM briefs in plain language.

**12. Link prediction — how?**
Cross-community common-neighbour scoring, weighted 3x when the shared neighbour
is a burner phone or shell company (shared covert infrastructure is a far
stronger signal than a shared acquaintance).

**13. What if criminals stop using phones/banks?**
The graph is source-agnostic: any relationship type becomes an edge — hawala
informant reports, social media, vehicle movements, co-location. More sources =
denser graph, and jail co-location (which we already ingest) can't be avoided.

**14. Deployment cost?**
FOSS stack end to end. Cost is only compute (NIC MeghRaj cloud) + integration
engineering. No per-seat licences, unlike foreign alternatives.

**15. Security of the system itself?**
Air-gapped deployment option, RBAC, TLS everywhere, the audit chain, and no
external API calls in production (on-prem LLM). It's designed for the
Blockchain & Cybersecurity theme from the ground up.

**16. Can it work in real time?**
Yes — ingestion is incremental (`/api/rebuild`); new FIRs/CDRs update the graph
in seconds. Alert rules (e.g. call-spike near a watched node) push notifications.

**17. Who are the users?**
District cyber cells, SP-level investigators, state CID, and NCRB analysts.
UI needs zero data-science training: upload → click → read the brief.

frontend, docs/PPT. Decide this before judging!)

**19. What's next after the hackathon?**
Pilot with one district's historical (anonymized) data; measure time-to-lead
vs manual investigation; then Neo4j + IndicBERT productionization.
